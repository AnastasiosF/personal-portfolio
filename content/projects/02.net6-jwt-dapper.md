## Why

Most .NET API templates reach for Entity Framework by default. For services that are mostly
reads with hand-tuned SQL, Dapper is lighter and keeps the queries visible. This template is the
setup I kept rebuilding by hand, packaged once so a new service starts from a working baseline.

## What is in the box

- Token issuing and validation with `Microsoft.AspNetCore.Authentication.JwtBearer`
- Role claims and `[Authorize(Roles = "...")]` wired end to end
- A thin repository layer over Dapper with parameterised queries
- Swagger with the bearer scheme configured so you can test protected routes in the browser

## A representative query

```csharp
public async Task<User?> FindByEmailAsync(string email)
{
    using var connection = _connections.Open();
    return await connection.QuerySingleOrDefaultAsync<User>(
        "SELECT Id, Email, PasswordHash, Role FROM Users WHERE Email = @Email",
        new { Email = email });
}
```
